# Lessons

- When recognizing external agent or tool processes inside tmux panes, prefer matching configured fragments against the pane process and descendant process commands. Avoid relying only on `pane_current_command`, because wrappers can expose misleading names like Node versions or architecture-specific launcher names.
- Do not turn a reversible retention-policy choice into an upfront architecture gate. Separate durable facts from transient work state, preserve both options in the design, and defer deletion timing until there is an operational need or measured storage evidence.
- For a daemon change, source tests and review are not the delivery boundary. If the request is to make the running service work, completion requires building the deployable artifact, installing it through the documented workflow, restarting the daemon, and exercising the live ingress-to-handler path.
- When a public optional value has an associated update timestamp, model and test them as one presence-aware pair. Define preserve, set, clear, and fallback-selection semantics explicitly, including the exact downstream copy for the both-absent case.
- Do not assign destructive meaning to an empty legacy proto3 scalar when absence and empty are wire-indistinguishable. Reserve clear semantics for a presence-aware field and treat legacy empty input as no change.
- When one acquisition sample can produce independent facts, model each fact as optional and persist any useful subset. Do not require one classifier to succeed before recording another valid observation from the same sample.
- Treat every type that temporarily carries raw process or screen text as a privacy boundary: omit or manually redact `Debug`, strip complete terminal control strings including C1 forms, and test that sentinel secrets cannot escape diagnostics.
- Reserve sentinel identifiers against user configuration, and make ambiguous identity resolution typed before logging or projection so a configured provider cannot collide with the unknown identity.
- Treat an accepted slice as an integration gate, not as overall completion. Before reporting completion, reconcile the latest authorization against every unchecked task in the approved implementation plan and continue while any authorized work remains.
- Reconcile summary precedence by semantic recency, not by source class alone: a substantive prompt visible while Busy is the current instruction and must replace a retained completed summary; an Idle placeholder must be rejected while the most recent substantive completed summary remains available.
- Do not substitute fake-port or disposable-process verification for an explicitly required real-provider acceptance gate. Record each real provider, concurrency combination, dashboard transition, and external blocker separately so partial live evidence cannot be reported as a full pass.
- An ingress filter does not repair already-durable invalid candidates. When a newly forbidden value may exist in event history or current projections, add a durable reconciliation transition that invalidates the historical candidate and prove restart replay keeps it cleared without matching legitimate containing text.
- When a coordinator owns an isolated live process, resolve its tmux pane, current command, exact configuration, store, and launch command before replacing it. Reuse that launch surface for replay acceptance; a different local configuration is not equivalent evidence even when it binds the same port.
- Do not assume a meaningful submitted prompt remains adjacent to the composer or inside the visible tmux grid. Keep frequent state capture small, but let a provider-specific recovery adapter search a configurable styled scrollback tail on bounded recovery triggers; distinguish submitted history from the composer before selecting text.
- Do not assign retained tmux scrollback to a replacement process merely because the pane has a new incarnation identity. Baseline the recognised prompt sequence for each incarnation and require later ordered overlap before treating a prompt as newly observed work.
